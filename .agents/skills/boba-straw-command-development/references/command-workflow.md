# 命令扩展开发流程

## 1. 检查基线与范围

读取 git 状态、相关公共接口、实现和测试。区分已有方法、Raw 出口、缺失选项和缺失测试。
目标只给出数据结构时，先给出缺口分组，不能把“补齐 Stream”解释为无限扩展内核。
从当前源码核对 API，不凭历史对话或未验收规划声称功能已支持。

架构规则以根 AGENTS.md 和架构决策为准；涉及协议、连接或取消时另读
[网络模型](../../../../docs/architecture/network-model.md)。
记录 HEAD；若有未提交修改，说明验证覆盖当前工作树，不将 HEAD 当作完整验证版本。

## 2. 核实服务端语义

使用官方命令文档核实语法、参数数量、互斥选项、命令和选项的最低版本、空返回、
错误返回及 RESP2/RESP3 差异。记录来源链接与核实日期；无法获取可靠资料时标明待核实。
Redis、Valkey 和第三方模块支持分别声明，不能用一个服务端的通过代替另一个。
版本说明用于兼容性判断，不改变当前客户端协议协商策略。

按具体形式分类（例如普通读取与带阻塞选项的读取），至少确定：

| 维度 | 开发前确定 |
| --- | --- |
| 参数 | 固定/可变参数、数量前缀、选项组合、编码次序 |
| Key | 无 Key、固定位置、可变位置或参数决定位置 |
| 连接 | 共享普通命令、阻塞、事务、订阅或改变连接状态 |
| 返回 | 标量、嵌套聚合、空值、协议差异、特殊 Push |
| 路由 | 单 Slot、多 Key 同 Slot、跨 Slot 拒绝或明确的已有策略 |
| 效果 | 读写及管理副作用，仅用于语义审查，不授权重试 |

无 Key 命令也需说明 Cluster 节点选择。多 Key 默认不隐式拆分。
如果现有拓扑能力不满足要求，明确限制，不能在新增方法后提升整体拓扑支持承诺。

## 3. 确定 API 与前置依赖

沿用相邻命令的公开接口和结果类型，检查同步、CompletionStage、String、byte[] 各自范围。
不为了凑对称性虚构尚不存在的 facade；不覆盖的接口注明原因。
新增重载注意 null 调用歧义，接口新增抽象方法注意第三方实现兼容，结果映射不得有损转换二进制。
区分合法空值、空集合和异常，不将失败转成成功默认值。

如果需要新连接能力，列出前置依赖、风险、适用测试和阶段划分。
已授权范围内按阶段实现；超出范围请求方向。禁止共享 Raw MULTI/WATCH/订阅/阻塞命令等绕路方案。
本流程不要求普通小改动也先取得额外批准。

## 4. 实现与验证

复用编码、路由、结果交付和连接管理。不另建执行线程模型，不增加响应式依赖。
同步接口基于既有异步路径；不要在 EventLoop 内执行阻塞等待或用户回调。
协议改动保持请求响应 FIFO；Push 独立分发，Attribute 不占普通响应位置。
超时/取消保留已发送请求的响应占位，未知执行结果不能静默重放。

按[验收清单](acceptance-checklist.md)增加测试。先运行针对性测试，再执行根目录 `mvn test`。
实际服务端测试使用已授权的测试环境、唯一 Key 前缀并只清理本次数据；不使用 FLUSHALL/FLUSHDB。
若测试依赖隔离环境或额外权限，明确请求或报告缺口，不转向生产探测。

## 5. 更新证据并交付

更新相关文档/示例中的命令、选项、版本、接口与限制。
覆盖清单尚未建立时，在任务交付或相关功能文档记录以下事实，不创建虚假的“全量覆盖”：

- 命令形式、公开方法、String/二进制及同步/异步范围。
- 实现：未实现/部分实现/已实现。
- 验证：未运行/通过/失败/不适用（需原因），按环境分别记录。
- 测试类/方法、运行命令、源码基线/工作树差异、JDK、服务端版本、协议、拓扑和结果。

没有环境属于“未运行”，不是“不适用”；旧报告不自动覆盖本次代码改动。
将来存在 `docs/commands/coverage.yaml` 时，按它的 schema 更新，不重复维护冲突的状态表。
代码审查报告给出文件位置、证据、影响和修复建议；仅要求审查时不得直接实施修复。

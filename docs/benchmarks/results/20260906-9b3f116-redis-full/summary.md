# Redis 7.4.2 full network baseline：`9b3f116`

本次正式 JMH 运行建立 Boba Straw 当前网络模型在 Redis 7.4.2 上的完整单版本基线，覆盖同步、
`CompletionStage`、异步窗口、Pipeline、String/`byte[]` 的 1 KiB/64 KiB/1 MiB value、共享
EventLoop 公平性和慢 callback 隔离。它用于后续版本回归比较，不是与其他客户端的横向对比，
也不构成生产容量承诺。

## 结论

- 22 个吞吐 workload、24 个 sample-time workload、3 个 fork 和所有 measurement 均正常完成，
  没有报告协议失败、超时或断连。
- 异步窗口 1024 达到约 **149.6k commands/s**；Pipeline 128 达到约
  **49.8k commands/s**。
- 同步 GET/SET 的 sample-time 平均延迟约 **2.42/2.29 ms**；单请求异步 GET/SET 约
  **3.44/2.92 ms**。吞吐模式与 sample-time 模式具有不同采样开销，不能用吞吐倒数替代表中延迟。
- Pipeline 128 按单命令归一化后的平均延迟约 **24.3 us**，整批 128 命令的估算时间约
  3.11 ms。异步窗口延迟也按单命令归一化，不能解释为单个请求独立 RTT。
- 共享 EventLoop noisy Pipeline 场景中，健康 GET 平均/P99 为 **3.56/10.70 ms**，同期辅助计数
  为 1,137,920 条 noisy commands；慢 callback 场景健康 GET 平均/P99 为 **2.20/7.35 ms**，
  同期辅助完成计数为 5,769。
- 1 MiB binary GET/SET 分配约 **1,052,160/1,051,516 B/op**；String 对应约
  **2,100,504/2,099,866 B/op**。两条路径稳定相差约一个 1 MiB payload，再次确认第 2x 主要来自
  String/UTF-8 转换，而不是 NIO 内核再次复制。
- 本 run 与 Valkey baseline 使用相同的核心运行时代码、已有 workload 和机器配置，但执行时间不同且
  没有采用交错 A/B 顺序；吞吐和延迟差异只能作为各自基线，不能归因于 Redis/Valkey 服务端实现。

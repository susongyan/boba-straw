# Redis 命令扩展 Skill 与开发使用指南设计

状态：D1 文件与入口已落地；D2–D4 待实施。日期：2026-09-18。

本文设计两个交付物：`boba-straw-command-development` Skill 和面向研发的命令扩展使用指南。
专项 Skill、两份 reference、任务模板和[使用指南](../development/command-extension-guide.md)已创建。
覆盖清单、schema、检查器、专用 CI 门禁及分发仍是拟议方案；跨模型行为验证尚未执行。
本次不新增 Redis 命令、不修改客户端行为、不安装或发布 Skill。

## 1. 目标与边界

让维护者在不同 AI Agent、模型和会话中，用统一流程扩展 Redis 数据结构命令；
一致性指架构约束、API 风格、命令语义和验收标准一致，不要求生成相同代码。

适用任务：新增命令、补齐已有命令选项、补齐二进制接口、修正返回映射，以及审查命令实现。
不自动承接：业务接入、网络模型重写、服务端模块开发、全部命令自动生成、环境安装和发布。
Redis 模块命令或 Valkey 特有命令须显式确定服务端范围，不能默认属于通用 Redis 命令支持。

权威来源分别为：

- 仓库约束：[AGENTS.md](../../AGENTS.md)。
- 架构与失败语义：[架构决策](../architecture/decisions.md)及[网络模型](../architecture/network-model.md)。
- 命令参数及服务端行为：开发时核实的官方命令文档，并记录版本和来源。
- 实现状态：当前源码、测试和实际验证记录；规划文档不能作为已支持的证据。

Skill 不复制架构全文，不将参考示例当作强制设计。规则与现有实现冲突时，报告差异，
不复制历史缺陷；公共 API 的不兼容修复须单独提出方案。

## 3. 发现、触发和跨 Agent 使用

专项 Skill 的 description 明确“在 Boba Straw 源码仓库新增、扩展或审查 Redis 命令”，
排除业务应用调用命令的普通接入任务。保持允许隐式触发，不强制用户每次写 Skill 名称。
后续在根 AGENTS.md 增加简短路由，要求命令扩展任务读取专项 Skill。

支持 Skill 发现机制的工具可以自动选择；不能承诺所有工具都识别 `.agents/skills`。
不支持的工具使用项目规则入口或用户提示，显式读取同一个 SKILL.md。
工具适配层只放入口引用，不复制核心规则，不假定其他工具支持特定插件格式。

任务开始时简要确认：本次使用的 Skill、源码基线、目标命令、验收范围。
不要求模型输出隐含推理；以引用的文件和随后产出的测试证明执行情况。
无法读取 Skill 或必要规范时必须说明，不宣称已遵循；可以继续只读调查，不能猜测约束。

## 4. 任务输入与开发工作流

任务输入区分必需目标和可推导信息。用户给出命令或数据结构目标即可开始盘点；
版本、接口风格和测试命令优先从仓库获得，只有影响范围或安全的选择才询问用户。

标准任务模板包含：

- 命令、子命令或选项范围，以及明确不做的部分。
- 目标服务端及版本、拓扑、String/byte[] 和同步/异步接口范围。
- 可用测试环境及测试数据范围；没有环境时不得连接生产服务探测。
- 是否允许新增内核能力、变更公共 API、启动环境、提交或推送。
- 验收标准和阶段划分；权限未说明时不由 Skill 自动授权。

执行顺序：

1. 盘点已有命令、接口、路由、结果类型和测试，读取相关架构规则。
2. 核实官方命令语法、选项引入版本、返回结构及错误行为。无法核实时标为待确认。
3. 做命令分类，确定实现是否依赖缺失的连接、路由或协议能力。
4. 对齐现有公共 API；新增结果对象、重载或泛型要说明必要性和源码/二进制兼容性。
5. 实现参数编码、结果映射及必要路由，复用执行内核，不增加隐式重试。
6. 运行适用测试，更新覆盖事实和使用示例，复核资源及响应顺序。
7. 交付改动、测试证据、未验证项和已知限制；仅在授权范围内提交。

小型普通命令可以直接完成；若任务需要尚不存在的内核能力，先报告依赖、风险和分阶段方案。
用户已授权的前置能力可按阶段实现，超出范围则请求方向；不能用共享连接 Raw API 绕过隔离。
审查模式执行盘点、分类、验证和报告，不默认修改实现。

## 5. 命令分类规则

| 维度 | 必须确定的事实 | 影响 |
| --- | --- | --- |
| 参数 | 固定/可变参数、互斥选项、数量前缀、选项版本 | 参数校验和编码测试 |
| Key | 无 Key、固定位置、可变位置、选项决定的位置 | Cluster 路由与同 Slot 检查 |
| 连接 | 普通、阻塞、事务、订阅、改变连接状态 | 共享或专用连接及释放策略 |
| 返回 | 标量、聚合、嵌套、空值、RESP 差异 | 结果类型与解码测试 |
| 效果 | 读取、写入、管理操作及组合行为 | 错误语义和测试隔离，不自动决定重试 |
| 可用性 | Redis/Valkey、最低版本、模块依赖 | 支持声明及测试环境 |

同一命令的不同形式可以分类不同，例如是否带阻塞选项，不按命令名一刀切。
多 Key 不隐式拆分；无 Key 命令也必须明确 Cluster 节点选择策略。
特殊 Push 不作为普通响应消费；Attribute 不得占用一个 pending request。
取消或超时不意味着服务端撤销，已发送请求的响应占位必须保持 FIFO 正确。
只读、幂等标签都不授权增加客户端自动重试。

## 6. 覆盖清单设计

每个条目对应命令形式，稳定 ID 包含命令/子命令/选项变体，避免一个“支持”掩盖部分选项。
顶层记录 schemaVersion。条目拟包含：

| 字段组 | 内容 |
| --- | --- |
| identity | 稳定 ID、命令 token、数据结构、形式/选项范围 |
| sources | 官方文档链接、核实日期、命令及选项最低版本 |
| semantics | Key 提取策略及实现引用、连接类型、Cluster 策略 |
| api | 公开类/方法签名、同步/异步与 String/byte[] 各自覆盖 |
| implementation | unimplemented / partial / implemented，限制与前置依赖 |
| verification | 各测试场景的 not_run / passed / failed / not_applicable |
| evidence | 测试类/方法、验证命令、源码提交、服务端版本、JDK、协议、拓扑、报告位置 |

实现状态与验证状态分离：不存在不带环境范围的“全面已验证”。
not_applicable 必须有原因；缺少环境是 not_run，不能写成不适用。
验证记录引用实际代码提交；文档后续提交不要求递归地更新自身 SHA。
涉及实现或测试的后续变更，需要重新确认受影响证据，旧通过记录不得代表当前改动已通过。

清单初始化只导入已核实条目，未盘点部分标记未盘点；不能因为 Raw API 可发送就认为有类型化支持。
YAML 校验依赖若引入，只用于开发工具，不进入核心运行时。

## 7. 验收与 CI 分工

| 适用情况 | 验收内容 |
| --- | --- |
| 所有新增接口 | Java 8、参数边界、编码参数顺序、返回映射、服务端错误、公共 API 兼容 |
| String/二进制 | 编码约定、空值区别、空字节数组、非 UTF-8 往返 |
| 协议差异 | RESP2/RESP3、空聚合/空值/嵌套结构；不能只测成功样例 |
| 修改解码器 | 字节级分片、多帧、畸形输入、Push/Attribute 与 FIFO |
| 多 Key/Cluster | Key 提取、Hash Tag、同 Slot、跨 Slot 策略及适用路由行为 |
| 阻塞/状态型 | 专用连接、超时取消、部分写出/已写出、恢复或销毁、资源释放 |
| Pipeline/事务适用 | 顺序及部分错误语义；不能把批量当原子事务 |
| 修改共享内核 | 相关生命周期/并发回归；必要时才增加性能对比 |

始终执行 `mvn test`，再按影响范围运行集成与兼容性测试；未跑的维度在报告中明确列出。
单元测试不能代替真实服务端兼容性测试，普通命令扩展也不强制全量性能压测。

拟新增机械门禁：清单 schema/ID 唯一性、必需证据字段、文件/链接存在、示例编译、已有 Java 8
及依赖门禁。方法签名与清单映射检查只有在可靠解析实现后才列为已启用。
语义分类、重试风险、连接所有权和兼容性仍需人工确认；AI 审查不作为唯一发布批准。
前置格式校验通过只证明 Skill 格式有效，不证明 Agent 会正确开发。

## 8. 开发使用指南内容

指南按“第一次使用 → 派任务 → 验收 → 排障”组织，提供以下可复制示例。

### 自然语言与显式调用

```text
补齐 Set 的剩余普通命令。先检查命令覆盖，按仓库命令扩展 Skill 开发。
本次不新增连接管理能力，不提交或推送，交付实际测试结果和未验证项。
```

```text
使用 $boba-straw-command-development 补齐 Stream 命令。
先按普通、阻塞、管理命令分组，列出前置依赖与分阶段计划，再实施已确认范围。
```

### 不支持 Skill 自动发现的 Agent

```text
读取 AGENTS.md 和 .agents/skills/boba-straw-command-development/SKILL.md，
按其中引用的流程补齐指定命令。先确认能读取这些文件；缺少资料时报告，不假设已加载。
```

### 只读审查

```text
按照命令扩展验收规则及 boba-straw-review 审查已有实现，不修改代码。
输出文件位置、证据、影响和建议；未运行的测试不能写成通过。
```

指南还解释：命令清单在哪里、如何选择测试环境、如何继续中断任务、如何处理旧 Skill 与新源码
不匹配，以及如何区分“Skill 未加载”“执行未遵循”和“规则本身遗漏”。
恢复任务时读取当前 git diff 和最近验收记录，不依赖上一会话记忆，不覆盖既有工作区修改。

标准交付包含：命令/选项与 API 范围、架构和兼容性影响、测试命令与结果、
未验证维度、覆盖清单变更、限制和后续动作。不要只给出“完成”结论。

## 9. Skill 验证、版本与分发

先做格式、相对链接及任务模板检查，再用隔离练习验证行为：

- 普通命令：能沿用 API、补测试，而非创建另一套执行内核。
- 阻塞形式：能识别专用连接前置依赖，不静默使用共享连接。
- 多 Key：能识别动态 Key 位置并遵守跨 Slot 策略。
- 取消/未知结果：不会把超时当未执行并增加重试。
- 只读审查/环境缺失：不修改代码、不虚报通过。
- 规则不可读或版本不匹配：明确说明限制，不假装已加载。

记录 Agent/模型、Skill 版本、源码基线、任务输入、实际产出和人工评审结论。
需要独立 Agent 验证时另行取得授权；本设计不自动启动子 Agent。
不将有限样例通过宣传为所有模型都可靠；后续真实失败驱动小范围修正规则。

开发 Skill 跟随源码维护，发布包有独立版本，并记录适用源码 ref/提交、规范版本及制品 hash。
安装版与仓库版不一致时，优先使用当前仓库经维护的规则，并报告冲突，禁止静默混合。
离线包必须包含被引用的规范快照并校验链接；不只是复制一个 SKILL.md。
私有仓库/市场格式留在发布适配层，开发流程本身保持厂商中立。
许可证未确定前不公开发布；本方案不实现上传渠道，也不承诺跨工具统一安装命令。

## 10. 分阶段落地与完成标准

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| D1 | 专项 Skill、两份 reference、任务模板、使用指南、入口路由 | 链接有效，范围明确，自然语言与显式入口可读 |
| D2 | 覆盖 schema、首批真实命令盘点、校验工具 | 正例通过；重复 ID、缺证据、错误状态等反例被拒绝 |
| D3 | 普通及特殊命令的试运行、指南修订 | 留存真实测试及行为证据，未运行维度如实列出 |
| D4 | CI 门禁、版本化分发对接 | 可复现构建、包内引用完整，许可和版本检查生效 |

每阶段先验收再按用户授权提交。D1 不依赖全命令盘点；D3 优先使用已有实现进行审查练习，
不为测试 Skill 擅自扩大功能开发范围。尚未完成 D1 前，不宣称专项 Skill 已经自动生效。
